# us_28721 — Vulkan decode-FA on Xe2: fix deep-context collapse (upstream)

**Type:** New kernel/ plumbing contribution (the one place we write code instead of polishing a PR).
**Upstream refs:** ggml-org/llama.cpp #28721 (B70 Vulkan decode 35.6→4.5 t/s at 64K ctx vs SYCL 15.8 — OPEN), analysis threads #24408/#24406 (FA shader selection, merged part), #29357 (Intel FA *prefill* kernel, open), #26581 (Xe2 attention latency tax: ~21–25 ns/KV-pos/full-attn-layer, both backends), merged today: #29476 (GDN tuning — proves Intel-specific dispatch rewrites are welcome and land fast).

## Persona
Me: wants Vulkan as the fallback/compat track on the rig; today Vulkan is unusable beyond ~16K ctx on qwen4exp for this backend because decode takes a scalar path that never engages XMX matrix cores.

## Story
As a Vulkan-on-Intel user,
I want the decode attention kernel to dispatch the FA shader (matrix-core/red-atomic path) per Q-head when `n_rows==1`, instead of falling back to scalar `soft_max`/`sd`,
so token generation at 32K–256K context doesn't collapse ~8x versus SYCL.

## Rationale (evidence)
- #28721's own trace: collapse is attention-side, not KV-bandwidth-side; FA shader selection avoids the `sd` path pattern the report describes; the batched (`n_rows>1`) FA path already exists for AMD with red-atomics (per #24406/#24408) — the dispatch condition excludes the single-row decode case on Intel.
- #26581 quantifies the residual latency tax (useful ceiling data if kernel lands: don't expect zero-cost deep ctx, expect SYCL-parity class).
- #29476's merge pattern (single-arch dispatch specialization, ~10x op-level win, merged same-week) is the template for acceptance.

## Acceptance criteria
1. Prototype on master ≥ b11261: extend the Vulkan FA dispatch so `n_rows==1` + `head_count_kv≤2` (our QSA config: 24 Q-heads/2 KV-heads) selects the FA shaders with per-head red-atomic accumulation; no fairness-vs-#29357 duplication — coordinate in-thread first (prefill kernel author likely receptive to a decode counterpart).
2. Correctness: greedy parity vs `-fa off` reference for 500 tokens at 8K and 32K ctx (hybrid-state bug-class gates per §8 ladder item 2); q8_0 and f16 KV both pass.
3. Bench: llama-bench `tg128 -d 32768 -d 65536` on B70 Vulkan ≥2x current master, ≤1.3x gap vs SYCL at same ctx; short-ctx tg regression ≤3%.
4. Upstream as follow-up to #28721 / alongside #29357 (prefill+decode pairing), full approval flow: comment intent in #28721 before pushing a PR, CC maintainers; PR carries before/after tables (our rig + volunteer other Intel cards from the #26581 reporter if offered).
5. If rejected/stalled: keep as documented fork patch in local runbook (this is the sanctioned fallback for kernel work the research flagged as "biggest Vulkan-side win").
