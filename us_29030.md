# us_29030 — Lazy-tensor row gathering via direct reads (upstream)

**Type:** Cherry-pick/revive existing upstream direction (not new code).
**Upstream refs:** ggml-org/llama.cpp #29030 (gather lazy rows with direct reads, open), #29599 (`llama_prefetch_rows` API + `--prefetch-rows`, open), #28136 (prototype, >2x prefill measured, closed unmerged).

## Persona
Me: single user running `unsloth/Qwen3.8-Flash-Next-GGUF` (qwen4exp) on a 64 GB-RAM box with Intel Arc Pro B70 ×2. The PLE/n-gram table (~29–36 GB across quant variants) lives on NVMe and is consumed row-wise via `--lazy-mode auto`.

## Story
As a llama.cpp user running models with huge lazily-mapped embedding tables (qwen4exp PLE, future ngram-heavy models),
I want lazy row reads to be gathered into batched, direct-I/O syscalls and prefetched during GPU compute,
so that prompt processing stops paying per-row page-fault + `madvise(DONTNEED)` + refault round-trips against my NVMe.

## Rationale (evidence)
- #28136 measured **>2x prefill** on a GB10-class offload rig by replacing row-at-a-time mmap faults with direct reads (closed unmerged; direction revived by #29030/#29599).
- PLE access pattern is pure random-row lookup (320M rows, 16 heads, offsets) — the worst case for page-cache-as-API and the best case for gather+prefetch.
- Strata (independent engine, docs/DETAILS.md) built its entire SSD-tier around exactly this pattern and reports ~400–1450 t/s pp on modest hardware; llama.cpp's current lazy path is the streaming bottleneck in our bench plan instead.

## Acceptance criteria
1. When a tensor is lazy (`LLAMA_LAZY_MODE_ON/AUTO`), the row-fetch path issues **one gather call per ubatch** (readv-style / single direct-read) instead of N faults.
2. `--prefetch-rows <n>` (and/or `llama_prefetch_rows` API) exists; prefetch of chunk *i+1*'s rows overlaps compute of chunk *i*; disabled by default keeps behavior bit-identical.
3. Page-cache friendliness: second identical prompt is not slower than first (prefetch must not thrash the warm cache); first-run pp gain ≥1.5x on NVMe vs master for UD-Q4_K_XL at 8K prompt (our rig, llama-bench pp512–pp8192).
4. No regression when lazy-mode is `off`; mmap-spanning Metal class bugs (#29465-analogs) covered by existing platform guards; Windows named-pipe-free path (OverlappedFileReadFileRanges) per #29030 design.
5. Review path: comment on #29030/#29599 with our measurements; offer to rebase/carry #28136's deltas if maintainers want a single consolidated PR. Do not fork silently — establish communication first.

## Definition of done
PR referenced/merged upstream or our rebased branch benchmarked on the rig (SYCL+Vulkan) and the pp numbers recorded in research.md §6.8 ladder.
